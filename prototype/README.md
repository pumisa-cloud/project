# ต้นแบบระบบเช็คลิสต์สำหรับการดำเนินโครงการ

ต้นแบบทำงานได้จริง (รันได้ในเครื่อง) ตามที่ออกแบบไว้ใน `../design-document.md`
ประกอบด้วย API + SQLite + หน้า Web สำหรับกำหนดกระบวนการ มอบหมายงาน ติดตาม และแจ้งเตือน

> ต้องการลองกดทันทีโดยไม่ติดตั้ง Node.js: เปิด `../demo/index.html` (ดู `../demo/README.md`)

## ความต้องการ

- Node.js 18+ และ npm

## การรัน

```powershell
# 1) ติดตั้ง dependency ของ API
cd prototype
npm install

# 2) สร้างข้อมูลตัวอย่าง (ผู้ใช้ 5 คน, แม่แบบ 2 แบบ, โครงการ 2 โครงการ)
npm run seed

# 3) รัน API (http://localhost:4000)
npm run dev

# 4) รันหน้า Web (http://localhost:5173) — เปิดเทอร์มินัลอีกหน้าต่าง
cd web
npm install
npm run dev
```

เปิดเบราว์เซอร์ที่ **http://localhost:5173**

> หากต้องการสร้างข้อมูล.DB ใหม่ ให้รัน `npm run seed` อีกครั้ง (จะลบข้อมูลเดิมในต้นแบบ)

## สิ่งที่ลองได้ในต้นแบบ

| เมนู | สิ่งที่ทำได้ |
|---|---|
| ภาพรวม | ดูจำนวนโครงการ งานเลยกำหนด งานใกล้ถึงกำหนด |
| โครงการ | สร้างโครงการจากแม่แบบ → ระบบสร้างขั้นตอนอัตโนมัติ; เปลี่ยนสถานะโครงการ |
| รายละเอียดโครงการ | กำหนดผู้รับผิดชอบ/กำหนดส่งต่อขั้นตอน, เปลี่ยนสถานะ, เพิ่มรายการย่อย, ดู Kanban และประวัติการเปลี่ยนแปลง |
| แม่แบบกระบวนการ | สร้างแม่แบบพร้อมขั้นตอน ระยะเวลา บทบาท หลักฐานบังคับ และ dependency ระหว่างขั้นตอน |
| งานของฉัน | กรองงานของผู้ใช้ที่เลือก (ทั้งหมด / ใกล้กำหนด / เลยกำหนด) และกดทำเสร็จ |
| การแจ้งเตือน | ดูแจ้งเตือน อ่านแล้ว/อ่านทั้งหมด, เปิด-ปิดช่องทาง in-app และอีเมล |

ผู้ใช้ตัวอย่าง (เลือกได้มุมซ้ายล่าง): `admin=1`, `HR Manager=2`, `Training Officer=3`, `Line Manager=4`, `viewer=5`

### ทดสอบการแจ้งเตือน

- กด **“รันสแกนกำหนดเวลา (demo)”** ที่แถบด้านซ้าย เพื่อจำลอง cron ทุกวัน 08:00 น.
  ระบบจะตรวจงานที่ใกล้/เลยกำหนด สร้างแจ้งเตือน แจ้ง PM และเปลี่ยนสถานะเป็น `Overdue`
- เปลี่ยนผู้รับผิดชอบของขั้นตอน → ผู้ที่ถูกมอบหมายจะได้รับการแจ้งเตือน `Assigned`
- เปลี่ยนสถานะขั้นตอน → PM ได้รับการแจ้งเตือน `Status Changed`
- หน้า Web อัปเดตการแจ้งเตือนทุก 15 วินาที (Socket.IO พร้อมใช้งานฝั่ง API สำหรับ real-time)

### อีเมล

ค่าเริ่มต้นเป็น **dry-run** (พิมพ์ข้อความอีเมลลง console แทนการส่งจริง) หากต้องการส่งจริง:

```powershell
$env:EMAIL_DRY_RUN='false'
$env:SMTP_HOST='smtp.example.com'
$env:SMTP_PORT='587'
$env:SMTP_USER='user@example.com'
$env:SMTP_PASS='password'
$env:SMTP_FROM='no-reply@example.com'
npm start
```

## โครงสร้าง

```
prototype/
├── src/
│   ├── db.js          # schema SQLite (better-sqlite3)
│   ├── seed.js        # ข้อมูลตัวอย่าง
│   ├── server.js      # REST API + Socket.IO
│   ├── notify.js      # สร้างแจ้งเตือน + push + ส่งอีเมล
│   ├── scheduler.js   # ตรวจ due-soon / overdue (node-cron)
│   └── mailer.js      # nodemailer (dry-run default)
├── web/src/
│   ├── App.jsx        # ทุกหน้าของแอป
│   ├── api.js         # REST client
│   ├── ui.jsx         # Badge / Progress / fmtDate
│   └── styles.css
└── data/checklist.db  # สร้างอัตโนมัติตอนรันครั้งแรก
```

## ข้อจำกัดของต้นแบบ

- ยังไม่มี username/password หรือ JWT — เลือกผู้ใช้จากมุมซ้ายเพื่อจำลองบทบาท (เหมาะสำหรับ demo)
- ยังไม่มีการแนบไฟล์จริง, คอมเมนต์/@mention และรายงานเชิงวิเคราะห์ (อยู่ในเฟส 2–3 ของ roadmap)
- ใช้ SQLite แทน PostgreSQL และใช้ polling ฝั่ง Web แทนการเชื่อม Socket.IO client
